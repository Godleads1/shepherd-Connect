OBJECTIVE
==================================================

Investigate the remaining Task #75 reliability concern:

CROSS-INSTANCE REALTIME / CLASSROOM DISPLAY RELIABILITY

The previous audit found that classroom/display realtime currently relies on process-local SSE plus PostgreSQL LISTEN/NOTIFY.

Known facts from the prior investigation:

- API processes listen to PostgreSQL channel:
  classroom_display_refresh
- LISTEN/NOTIFY is ephemeral.
- Notifications are not replayable.
- Classroom/display persisted state remains authoritative.
- A reconnecting client can recover state by reading the persisted API state.
- The concern is therefore not that realtime is the source of truth.
- The concern is whether a realtime event can be lost, delayed, duplicated, reordered, or incorrectly treated as authoritative across multiple API instances/processes.

Determine the actual current architecture and whether this is a real production reliability problem, a UX degradation only, or both.
