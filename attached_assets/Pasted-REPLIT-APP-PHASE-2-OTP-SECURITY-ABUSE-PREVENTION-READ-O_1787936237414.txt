PR-03 — OTP ISSUANCE ABUSE
==================================================

Previously reported endpoint:

POST /api/auth/send-otp

Previously reported concerns:

- broad global rate limit is not sufficient
- repeated requests can generate many OTP records
- repeated requests can invoke paid SMS/email delivery
- no dedicated per-contact cooldown
- no strict outstanding-OTP policy
- abuse may exhaust provider credits

Inspect the actual implementation.

Determine:

1. Which registration/login/reset flows call send-otp?
2. Which contact types are supported?
   - email
   - phone
   - both
3. What rate limiting exists currently?
4. Is limiting:
   - per IP?
   - per account?
   - per contact?
   - global?
5. Can the same contact request many OTPs quickly?
6. Are previous OTPs invalidated?
7. Can multiple active OTP sessions exist simultaneously?
8. Are expired OTP rows cleaned?
9. What happens if SMS/email provider delivery fails?
10. Is an OTP persisted before or after provider success?
11. Can provider failures leave unusable or excessive OTP rows?
12. Can attackers use many IPs against one phone/email?
13. Does the response leak whether an account/contact exists?

==================================================
ATOMIC ONE-TIME CONSUMPTION
==================================================

Previously reported behavior:

OTP verification may:

1. read OTP
2. validate it
3. delete it

as separate operations.

This may allow concurrent verification of the same OTP.

Confirm the current implementation.

If confirmed, propose a database-atomic solution compatible with Drizzle/PostgreSQL.

Required invariant:

ONE OTP
→ MAXIMUM ONE SUCCESSFUL CONSUMPTION

Two simultaneous correct verification requests must NOT both succeed.

Evaluate the smallest existing-architecture implementation, such as:

- transaction + row lock
- conditional atomic update/delete
- DELETE ... RETURNING
- UPDATE ... WHERE unused/valid ... RETURNING

Do not choose until you inspect the current schema and Drizzle capabilities.
