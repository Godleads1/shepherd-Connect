==================================================
CONCURRENCY
==================================================

Operation lock MUST be acquired before command-specific domain locks.

For the same operation ID submitted concurrently:

Request B must wait for Request A.

If A commits:
- B replays A's result
- B performs no second domain mutation
- B produces no duplicate audit/outbox effect
- B does not generate another OTP

If A rolls back:
- B may execute the command once.

Do not implement:

SELECT operation
IF absent
INSERT operation

without an atomic uniqueness/claim mechanism.

FRONTEND
==================================================

Generate the UUID when the user confirms a new logical submission.

Do NOT generate it:
- on render
- per HTTP attempt
- during retry
- during reconciliation

Persist only minimal pending identity information.

Unknown transport outcomes must enter:

unknown/reconciling

rather than definitive failure.

Retry uses the SAME operation ID.

Reload preserves/reconciles the SAME operation ID.

Provide explicit distinction between:
- Retry same submission
- Check status
- Start new submission

Do not automatically start a new operation after timeout/network failure.

RESPONSE-LOSS TESTING
==================================================

For EACH of the five routes implement a genuine test-only post-commit response-loss seam.

The test must represent:

1. Real HTTP request.
2. Transaction commits.
3. Domain record exists.
4. Operation record exists.
5. HTTP connection is terminated/dropped before the client receives the response.
6. Client observes an unknown transport outcome.
7. Client retries with the SAME operation ID.
8. Server returns the original logical result as already_applied.
9. Exactly ONE domain mutation exists.
10. Exactly ONE audit/outbox effect exists.
11. No duplicate OTP is generated.
12. Optional SMS/provider work is not repeated by replay.

A mocked function exception is NOT sufficient proof.

If the current test harness cannot perform the connection-drop boundary accurately, STOP and report that limitation rather than claiming the test proves response-loss safety.
