# SHEPHERD CONNECT - FULL STACK BUILD SPECIFICATION

Build "Shepherd Connect," a mobile-first, intelligent Children's Church Management Platform. This is a production-ready full-stack application deployable on Replit. The app serves Parents, Teachers, Check-in Attendants, and Admins.

## BRAND IDENTITY
- Name: Shepherd Connect
- Tagline: "Safe. Known. Celebrated."
- Primary Color: Deep Royal Blue (#1e3a8a)
- Accent: Warm Gold (#f59e0b)
- Success: Emerald Green (#10b981)
- Danger: Rose Red (#f43f5e)
- Font: Inter (Google Fonts)
- Tone: Professional, warm, pastoral, trustworthy

## TECH STACK (REPLIT-OPTIMIZED)
- **Frontend:** React 18 + Vite + TypeScript + Tailwind CSS + shadcn/ui components + Lucide React icons
- **Backend:** Express.js + TypeScript + Node.js
- **Database:** SQLite with better-sqlite3 (or Prisma + SQLite)
- **Real-time:** Socket.io for live dashboards and notifications
- **Auth:** JWT (jsonwebtoken) + bcryptjs, Role-Based Access Control (RBAC)
- **QR/Barcode:** `qrcode` (generation) + `html5-qrcode` (scanning)
- **Facial Recognition:** `face-api.js` (client-side face detection and recognition)
- **Charts:** `recharts` for admin analytics
- **State Management:** Zustand
- **Routing:** React Router v6
- **Notifications:** In-app notification center + mock WhatsApp/SMS architecture (create service layer ready for Twilio/Termii integration)
- **PWA:** Include manifest.json and service worker setup for installability

## USER ROLES & AUTHENTICATION
Implement 6 roles with RBAC:
1. **Super Admin:** Full system access, user management, platform config
2. **Children Church Admin:** Manage classes, allocate teachers/children, view all reports
3. **Class Teacher:** View class roster, mark arrivals, complete appraisals, send notes
4. **Check-in Attendant:** Scan QR codes, verify identity, process drop-off/pick-up only
5. **Parent:** Manage family profile, view children classes, receive notifications, give feedback
6. **Delegate (Pickup Person):** One-time OTP verification only (no login required)

Auth Requirements:
- JWT with 24h expiry, httpOnly cookies
- MFA for Admin/Super Admin (TOTP simulation using speakeasy or simple email OTP)
- Automatic session timeout after 30 minutes inactivity
- All actions audit-logged with userId, timestamp, action, IP address

## MODULE 1: FAMILY REGISTRY (M1)
Progressive Registration Flow:
- **Stage 1 (Identity):** Full name, DOB, gender, phone (with Nigeria +234 formatting), email, facial photo capture using device camera (store face descriptor using face-api.js)
- **Stage 2 (Family):** Spouse/partner toggle (including single-parent option), residential address, children details form (repeater)
- **Stage 3 (Optional):** Place of work, emergency contact, special needs/medical notes (encrypt in DB), communication preferences (WhatsApp/SMS/Email/In-App)

Children Registration per child:
- Full name, DOB (auto-calculate age), gender, facial photo capture, allergies, medical notes, class assignment (admin assigns later)

Family Tree UI:
- Interactive tree visualization showing parents and children nodes
- Each child node displays: photo, age, current class, teacher name, last attendance
- Click child node → detailed profile with attendance calendar and appraisal history
- Timeline of class progression

## MODULE 2: CLASS ENGINE (M2)
Class Management:
- Admin creates classes with: name, age range, capacity, room/location, service slot (7am, 9am, 11am, 1pm), description
- Visual class cards showing current enrollment vs capacity with color-coded capacity bars (green &lt;80%, orange 80-99%, red 100%)

Teacher Management:
- Teacher profiles with availability calendar
- Drag-and-drop or form-based teacher allocation by date/class/service slot
- Rotation engine: auto-assign teachers across multiple Sunday services based on availability groups
- Teacher-to-child ratio monitoring (alert if &gt;1:15)
- Substitute nomination workflow with notification

Child Allocation:
- Admin dashboard to review unallocated children and batch-assign to classes
- Auto-suggest based on age and capacity
- Parent receives in-app notification on allocation
- Parent can request class change (pending admin approval)

## MODULE 3: CHECK-IN GATEWAY (M3)
Drop-Off Workflow (must complete in &lt;30 seconds):
1. Parent arrives → Check-in interface (kiosk mode or attendant tablet)
2. Parent presents QR code (generated in their profile) OR uses facial recognition
3. Scanning interface using html5-qrcode with beep sound on success
4. System displays: Parent photo, child(ren) photos, class assignments, allergies alerts (red banner if medical notes exist)
5. Facial recognition: capture face, match against stored face descriptor using face-api.js Euclidean distance &lt;0.6
6. Multi-child support: single QR can cover all children or individual codes
7. Timestamp recorded with: date, time, service slot, attendant ID
8. Real-time Socket.io event: class teacher receives in-app notification "Child Name dropped off, arriving at Class Name"
9. Child status updated to "In Transit"
10. Teacher marks child as arrived in class → second timestamp, status "In Class"
11. Parent receives confirmation notification: "[Child] is safely in [Class] with [Teacher]"

Offline Mode:
- If network drops, store check-in in IndexedDB, sync when connection returns
- QR codes should be scannable even offline (validate against cached data)

## MODULE 4: CHECK-OUT VAULT (M4)
Standard Pick-Up:
- System sends notification 10 mins before service ends: "Class dismissing soon"
- Parent presents QR or face scan at pick-up point
- System validates identity, displays child photo and class
- Teacher releases child, marks pick-up timestamp
- Status updated to "Picked Up"
- WhatsApp-style confirmation sent to parent

Delegate Pick-Up:
- Parent logs in → "Manage Pick-Up" → "Designate Someone Else"
- Enter delegate name, phone, optional photo
- System generates 6-digit OTP, displays to parent (mock SMS/WhatsApp send)
- Delegate arrives, enters OTP at pick-up station
- System verifies OTP, sends approval request to parent in-app
- Parent approves → child released
- Full audit trail recorded

Exception Handling:
- "Child Not Picked Up" alert 30 mins after service ends
- Admin dashboard shows list of children still in class with parent contact buttons

## MODULE 8: SHIELD PROTOCOL (M8)
Emergency Management:
- **Emergency Types:** Medical, Missing Child, Fire/Evacuation, Security, General
- **Levels:**
  - L1 (Class): Minor incident → Teacher + Coordinator notified
  - L2 (Department): Moderate → Admin + Parent notified
  - L3 (Building): Major → All staff + All parents in church
  - L4 (Community): Critical → All parents + Emergency services

Emergency Workflow:
- Big red emergency button in teacher/admin app with 4 quick-select options
- One-tap escalation levels
- Real-time incident thread (Socket.io room) for updates
- Broadcast system: push to relevant users based on level
- Auto-generated post-incident report with full timeline

Missing Child Protocol:
- Trigger from Check-Out Vault if child unaccounted for
- Display last known location (last class confirmed)
- Church-wide search mode: all devices show missing child photo and details
- Incident auto-documented for safeguarding

## FACIAL RECOGNITION IMPLEMENTATION
Using face-api.js:
- Load models from public/models (ssdMobilenetv1, faceLandmark68Net, faceRecognitionNet)
- During registration: detect face, extract descriptor (128-float array), store as JSON in DB
- During check-in: capture video frame, detect face, extract descriptor, compare against stored descriptors
- Match threshold: Euclidean distance &lt; 0.6
- Privacy: Show "Opt-in" toggle. If disabled, QR-only. Allow deletion of biometric data.
- Fallback: If face unclear or no match, immediately fallback to QR without error state

## CRITICAL USER FLOWS TO IMPLEMENT
1. **New Family Onboarding:** Landing → Register → Add Children → Wait for Admin Allocation → Receive Notification → Generate QR
2. **Sunday Drop-Off:** Parent opens QR → Attendant scans → Teacher confirms arrival → Parent gets confirmation
3. **Sunday Pick-Up:** System alerts → Parent scans → Teacher releases → Confirmation sent
