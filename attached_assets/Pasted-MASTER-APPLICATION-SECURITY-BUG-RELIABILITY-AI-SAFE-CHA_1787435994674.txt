PART T — AI SAFE-CHANGE PROTOCOL
==================================================

Design a mandatory protocol for EVERY FUTURE AI CHANGE.

The AI must follow this sequence:

1. READ relevant existing code first.
2. IDENTIFY affected files.
3. IDENTIFY tests protecting current behaviour.
4. STATE proposed change.
5. STATE possible regressions.
6. Make the SMALLEST necessary change.
7. Do not refactor unrelated code.
8. Do not replace working architecture unnecessarily.
9. Run existing tests.
10. Add tests for new behaviour.
11. Run lint/typecheck/build.
12. Show exact changed files.
13. Show diff summary.
14. Report failures honestly.
15. Never suppress failing tests just to obtain green results.
16. Never delete tests unless explicitly approved.
17. Never change database schema silently.
18. Never change authentication/authorization silently.
19. Never change environment variables silently.
20. Never modify production infrastructure/data without explicit approval.
